# Desk Buddy — Implementation Plan

Source of truth: `desk-buddy-claude-code-prompt.md` (spec) + `docs/prototype.html` (behavioral reference).
Spec wins on conflict. Every phase ends with: `flutter analyze` clean → tests green → `docs/progress.md` updated → **stop for review**.

Dev machine: Windows 11, Flutter 3.44.8 / Dart 3.12.2. **macOS cannot be built or verified here** (see §Open questions).

## Cross-cutting rules (enforced by code, not just by convention)

| Rule | Enforcement |
|---|---|
| No reminder-specific logic | `test/guards/no_hardcoding_test.dart` scans `lib/**.dart` for `water\|drink\|glass\|sip` (word-boundary, case-insensitive) and fails if found. |
| No `DateTime.now()` | The same guard test fails on `DateTime.now(` anywhere in `lib/` except `lib/core/clock/`. |
| Pure-Dart engine | Guard test fails if any file under `features/scheduler/engine/` or `shared/template/` imports `package:flutter`. |
| Strings in one place | `lib/shared/strings.dart` (a `Strings` class of consts/functions); ARB files can come later. |
| Time zone safe | All wall-clock math goes through a `WallClock` interface (see Phase 4), never `ms + 86400000`. |

Because of these guard tests, the grep rule runs on every `flutter test`, not only when someone remembers to grep before finishing a phase.

## Phase 1 — Overlay spike

Lives in `lib/spike/`, launched with `--dart-define=SPIKE=A|B`. It's deleted after the decision; only the winning service moves into `core/window/`.

**Shared:** a 120×222 placeholder (circle + body rect) walks along the bottom of the work area, turns at the edges, can be dragged, and responds to a tap.

- **Option A (moving small window):** window ≈ buddy + bubble area (~320×420). Each frame computes x and calls `windowManager.setPosition`, throttled to 30 and 60 Hz variants. The window is frameless, `setAlwaysOnTop(true)`, `setSkipTaskbar(true)`, transparent background.
- **Option B (full-screen overlay):** the window covers `display.visiblePosition/visibleSize`. `setIgnoreMouseEvents(true)` by default. A 50 ms timer reads `screenRetriever.getCursorScreenPoint()` and toggles click-through when the cursor enters or leaves the buddy/bubble hit rect, expanded by 8 px.
- **Windows runner work for both:** a transparent, flicker-free first frame. Start hidden, set the background to `Colors.transparent`, and show after the first frame. This may need `DwmExtendFrameIntoClientArea` in `windows/runner/flutter_window.cpp`.
- **Display handling:** pick the display that contains the buddy's center. Re-query on `screenRetriever` display events and on window move. Clamp to the work area, so the buddy stays above the taskbar wherever it's docked.
- **Measure:** frame build/raster times via `SchedulerBinding.addTimingsCallback`, process CPU % sampled with `Get-Counter '\Process(desk_buddy)\% Processor Time'` over 60 s of walking, plus visible jank (screen recording). Test at 100% and 150% DPI, and on a second monitor if one is available.
- **macOS:** the code paths are written (`LSUIElement`, `NSWindow.Level.floating`/`.statusBar`, `collectionBehavior = canJoinAllSpaces | fullScreenAuxiliary`, clear background in `MainFlutterWindow.swift`), but **click-through must be verified on a Mac by you**. I'll give a checklist.

**Expectation going in:** Option A is likely simpler and good enough on Windows, because `SetWindowPos` is cheap and needs no click-through hacks. Option B gives smoother motion on macOS but costs constant cursor polling. The spike decides. A per-platform split is allowed if the numbers say so.

**Deliverable:** `docs/decisions.md` entry with numbers + the `OverlayWindowService` interface (`moveBuddyTo`, `setInteractive`, `workArea`, `onDisplaysChanged`) that the rest of the app codes against.

## Phase 2 — Buddy rendering & movement

- **`BuddyPainter`** (`features/buddy/render/`) ports `charSVG` part by part in the 120×222 viewBox, using `canvas.scale(size/120)`. Each part is its own method in the spec's z-order. SVG paths become `Path` builders, and `shade()` is ported 1:1.
- **`BuddyPose`** (an immutable value): legL, legR, armR, armL angles, bodyDy, eyeScaleY, flip. The painter is a pure function of `(BuddyLook, propId, BuddyPose)`, which makes it golden-testable.
- **Animation:** one `Ticker` drives a `BuddyAnimator` state machine (`walking/idle/alert/dragging`) that outputs a `BuddyPose` from elapsed time. It's cheaper than several controllers, and the ticker can stop when idle. Blink is a 4.5 s timer-driven pulse in every state.
- **Prop registry:** `features/buddy/render/props.dart` holds `const Map<String, PropPainter> propRegistry`, with `none`, `bottle`, `coffee`, `book`, `phone`, `dumbbell`, `pill`. Display names come from the same map, so the UI dropdowns read it too.
- **Movement:** `BuddyMover` (pure Dart, injectable `Random` and time) handles walk 4–11 s / idle 1.5–5 s, the 40% turn chance, edge bounce, and the walk-disabled state.
- **Input:** drag via `GestureDetector`/`Listener` (in Option A this moves the window). Movement under 4 px counts as a tap and shows the 2.8 s peek bubble. Enter/Space on a focused buddy does the same.
- **Bubble widget:** stroked text uses two stacked `Text` widgets (a stroke `Paint` + the fill). It has the pop-in spring animation, clamping above the buddy, and a flip below when there's no room above.
- **Reduce motion:** read `MediaQuery.disableAnimations` (Windows: driven by the OS animation setting). It freezes limbs but the buddy still moves.
- **Position persistence:** a `BuddyPositionStore` interface. A temporary JSON-file implementation goes in now and is swapped for the Settings row in Phase 3.
- **Tests:** golden tests for 4 looks × 3 poses, plus unit tests for the mover and animator state transitions.

## Phase 3 — Data layer

- Drift tables match spec §4: `categories`, `reminders` (`daysOfWeek` as a JSON text converter, `scheduleType` and `action` as `intEnum`/`textEnum`), `log_entries`, `buddy_look` and `settings` (single-row tables with a fixed `id = 1`).
- Add nullable `source TEXT` to `reminders` now (default `'local'`). It costs nothing and covers the calendar non-goal's "easy to extend".
- Database path: `getApplicationSupportDirectory()/desk_buddy.sqlite`. Open with `PRAGMA journal_mode=WAL; busy_timeout=3000; foreign_keys=ON`.
- DAOs → repositories that map rows ↔ freezed domain models. Only repositories are exposed to features.
- **Seed:** on first launch (no categories row), load both JSON assets in one transaction, resolve starter categories by name (creating any that are missing), and insert the first 3 starters with `nextDueAt` from the engine.
- **Retention:** delete log rows older than 90 days on startup.
- **Migrations:** schema v1, with `drift_dev schema dump` into `drift_schemas/` and a generated schema-verification test.
- **Debug-only sample history:** `seedLog` is ported behind `kDebugMode` and a dev menu item. Rows get `sample = true` (an extra column so "Remove sample history" can find them).
- **Tests:** in-memory `NativeDatabase.memory()` for DAOs, seeding idempotency, pruning, and the migration test.

## Phase 4 — Scheduler

**Pure engine (`features/scheduler/engine/`, no Flutter imports):**
- `WallClock` interface: `toWall(epochMs) → WallTime(y,m,d,h,min,weekday)` and `fromWall(y,m,d,h,min) → epochMs`. The production version uses `DateTime(...)` local. Tests use a `timezone`-package `TZDateTime` implementation (e.g. `America/New_York`, `Europe/London`) so DST cases are deterministic on any machine.
- `computeNext(reminder, fromMs, wallClock)` and `fitWindow`, ported and hardened:
  - The interval window handles `a<=b` and overnight `a>b`, plus null bounds meaning all day.
  - Daily searches 8 days using wall-date arithmetic (`day + i` via `fromWall`).
  - DST gaps: a 02:30 time on a spring-forward day resolves to the next valid minute. Overlaps: on fall-back, the first occurrence. Both are documented in decisions.
- `fillTemplate(template, ctx)` replaces only the known tokens and leaves unknown ones as-is.
- `goals.dart`: `countToday`, `streak`, and dashboard ring math (sum of min(count, goal) ÷ sum of goals).
- **`SchedulerCore`**: a pure reducer. `(state, Event) → (state, List<Effect>)`.
  - Events: `tick(now)`, `respond(id, action)`, `setDnd`, `testFire(id)`, `remindersChanged`, `snoozeAll(minutes)`.
  - Effects: `showAlert`, `hideAlert`, `writeLog`, `updateNextDue`, `disableReminder`, `playChime`, `notify`.
  - This puts one-at-a-time queuing, earliest-first, DND, auto-miss, and the sleep gap (>2 min wall jump → each overdue reminder fires at most once, then reschedules from now) under plain unit tests.
- **Tests:** every case in spec §5, plus overnight window at exactly the boundaries, invalid `everyMinutes`, reminder deleted while its alert is open, and DND toggled while an alert is open.

**Service (overlay engine):**
- Uses `Timer.periodic(1s)` with `clock.now()`. It feeds the core and applies effects through repositories, then sends `dataChanged` (a no-op until Phase 5).
- The alert bubble has done and snooze buttons and shows goal progress. The buddy shows the reminder's prop.
- The chime plays through audioplayers.
- When `buddyVisible == false`, it uses `local_notifier` with done/snooze actions where supported (Windows toast actions yes; macOS falls back to click = open bubble). If those actions don't fire callbacks reliably, I'll note the fallback in decisions.

## Phase 5 — Dashboard window, tray, sync

- **Entry:** `main(args)`: `args.firstOrNull == 'multi_window'` → `DashboardApp(windowId, json args)`; otherwise `OverlayApp`.
- **Tray** (`core/tray/`, owned by the overlay): Open Dashboard (focuses it if already open), Show/Hide Buddy, DND (checkable), Snooze all 30 min, Quit. The icon assets are a `.ico` for Windows and a template PNG for macOS.
- **Channel protocol:** a sealed `WindowMessage` class with JSON codec — `dataChanged(tables)`, `testReminder(id)`, `setDnd(bool)`, `characterChanged`, `settingsChanged`. One `WindowBus` service wraps `DesktopMultiWindow.setMethodHandler`/`invokeMethod`. On `dataChanged`, the receiver calls `ref.invalidate` on the affected providers. All mutations go through repositories, which emit the message automatically, so screens can't forget to sync.
- Each engine opens its own Drift connection to the same file (WAL), so cross-engine writes need the bus.
- **Theme:** `ThemeExtension<DeskColors>` holds the spec tokens for light and dark, Baloo 2 headings, Figtree body, and the `themeMode` setting.
- **Shell:** a `NavigationRail` with 5 destinations. On a narrow window it moves to the top, following the prototype's ≤860 px behavior.
- **Screens:** match the prototype's layout and copy.
  - Dashboard: ring, goal rows with +1, facts, Coming up, Today.
  - Reminders: list + editor with show/hide fields, starter chips, validation strings.
  - Character: live preview with the same painter, presets, color pickers, chips.
  - Analytics: built with fl_chart. Stacked bars, goal line with a dashed goal, table, hour histogram, empty state.
  - Settings: all settings + categories editor + reset.
- Live countdowns come from a single `secondTickerProvider`, so there's no per-widget timer.
- `describe()` is ported to `shared/format/schedule_describe.dart` with unit tests.
- **Widget tests:** editor validation (3 messages), dashboard goal rows (+1 updates the count and bar), and empty states.

## Risks

| Risk | Mitigation |
|---|---|
| Transparent always-on-top window flickers or shows a black background on Windows | Runner tweaks in Phase 1. If window_manager can't do it, a small native plugin method. |
| `desktop_multi_window` second engine: plugins not registered in the sub-window | Register plugins via its `setWindowCreatedCallback` in the runner (a known requirement). Verify in Phase 5 day 1. |
| Two Drift connections → `SQLITE_BUSY` | WAL + busy_timeout + short transactions. Overlay writes are rare. |
| Per-monitor DPI and taskbar positions (left/top/auto-hide) | Use `visiblePosition/visibleSize` per display. Tested in the spike. |
| macOS untested on this machine | All macOS-only code is isolated in runner files + `core/window`. You get a Mac verification checklist each phase. |
| Rive runtime API churn | Rive sits behind `BuddyRenderer`. The painter stays the default. |
